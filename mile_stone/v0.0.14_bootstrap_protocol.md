# VEGA Bootstrap Execution Protocol
Version: v0.0.15

# Purpose

이 문서는 VEGA의:

```text
Environment-aware Orchestration Cognition
```

아키텍처를 실제 구현하기 위한:

- 부트스트랩 절차
- 단계별 실행 규약
- 검증 프로토콜
- 안정성 원칙

을 정의한다.

---

# Core Execution Philosophy

VEGA는 단순 자동화 시스템이 아니다.

목표는:

```text
Safe Semantic Infrastructure Runtime
```

을 구축하는 것이다.

따라서:

- 즉흥 구현 금지
- 추측 기반 수정 금지
- uncontrolled refactor 금지
- hallucinated architecture 금지

를 강제한다.

---

# Mandatory Workflow

모든 작업은 반드시 아래 순서를 따른다.

```text
1. 문서 읽기
2. 목표 확인
3. 작업 계획 제출
4. 승인 대기
5. 구현
6. 검증 테스트 작성
7. 검증 실행
8. 테스트 통과 확인
9. 다음 단계 진입
```

순서 생략 금지.

---

# Phase Execution Contract

각 단계는 반드시:

```text
Goal
 → Plan
 → Implementation
 → Validation
 → Verification
```

순서를 유지해야 한다.

---

# Forbidden Behaviors

다음 행동은 금지한다.

- 문서 읽지 않고 구현
- 목표 확인 없이 작업
- 계획 없이 코드 수정
- 검증 없이 다음 단계 진행
- 전체 리팩토링
- 안정 코드 수정
- command hallucination
- API hallucination
- undocumented abstraction 추가
- 임의 파일 생성
- 승인 없는 구조 변경

---

# Mandatory Approval Rule

작업 시작 전 반드시:

```text
작업 계획서 제출
```

을 수행한다.

승인 이전 구현 금지.

---

# Bootstrap Runtime Flow

# Step 1 — Read Target Document

반드시 대상 문서를 읽는다.

예:

- v0.0.14_goal.md
- environment_aware_orchestration_cognition.md
- architecture.md

---

# Step 2 — Extract Explicit Goal

문서에서:

- 목표
- 성공 기준
- 제약사항
- 안전 규칙

을 추출한다.

추측 금지.

---

# Step 3 — Produce Execution Plan

반드시 계획서를 생성한다.

계획서에는:

```text
- Goal
- Scope
- Affected Files
- Minimal Changes
- Validation Strategy
- Rollback Safety
- Risk Analysis
```

포함 필수.

---

# Step 4 — Await Approval

승인 이전:

- 구현 금지
- 코드 수정 금지
- 파일 생성 금지

---

# Step 5 — Minimal Implementation

구현 원칙:

```text
Precise Minimal Change Only
```

허용:

- 직접 관련 코드 수정
- 필요한 최소 구조 추가

금지:

- unrelated cleanup
- architecture rewrite
- speculative abstraction

---

# Step 6 — Validation Test Creation

구현 후 반드시:

- validation test
- failure test
- regression test

작성.

---

# Step 7 — Verification Execution

반드시:

```text
테스트 실행 결과
```

를 출력한다.

---

# Step 8 — Gate Check

모든 검증 통과 시에만:

```text
다음 단계 진입 허용
```

# LLM Coding Principles

# 1. Think Before Coding

추측하지 마라.

요구사항이 모호하면 질문한다.

접근 방식과 트레이드오프를 먼저 제시한다.

항상 가장 단순한 해결책부터 제안한다.

---

# 2. Simplicity First

코드는 최소한으로 작성한다.

요청되지 않은 기능 추가 금지.

과도한 추상화 금지.

---

# 3. Minimal Changes

정밀 타격 원칙 유지.

전체 리라이트 금지.

기존 스타일 유지.

---

# 4. Goal-Oriented Execution

반드시:

```text
Goal
 → Plan
 → Implementation
 → Validation
```

순서 유지.

---

# 5. No Hallucinated APIs

존재하지 않는:

- API
- 함수
- 라이브러리

생성 금지.

불확실하면 질문한다.

---

# 6. Stable Code Protection

검증된 코드는 건드리지 않는다.

직접 요청된 부분만 수정한다.

가능하면 diff 기반 수정 수행.

---

# 7. Context Confirmation

수정 전 반드시:

- 코드 맥락 확인
- 파일 확인
- dependency 확인

수행.

추측 구현 금지.

---

# 8. Rendering Isolation

그래프/뷰/파일 전환 시:

- framebuffer
- shader
- buffer binding
- WebGL state

강제 초기화.

시각적 간섭 차단 필수.

---

# 9. Mandatory Plan Approval

반드시:

```text
작업 계획 제출
 → 승인
 → 구현 시작
```

순서를 유지한다.

문서 읽지 않고 구현 금지.

문서 읽고 임의 작업 금지.

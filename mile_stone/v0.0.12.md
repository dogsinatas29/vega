# v0.0.12: Deterministic Fleet Management & Real-time Health Monitoring

## 목표
탐색(Discovery)에만 의존하던 기존의 불안정한 노드 식별 체계를 탈피하고, 최초 설정(Setup) 및 명시적 등록(Add-Node)을 통해 신뢰할 수 있는 '관리 대상 인벤토리(Fleet Inventory)'를 구축한다. 또한 실시간 생존 확인(TCP Probe) 기능을 통해 상태 보고의 무결성을 확보한다.

## 작업 내용
1. **Setup Wizard v2 (Inventory Registration)**:
   - `vega setup` 과정에 SSH 호스트 스캔 및 선택 등록 단계([3] Setup Fleet Inventory) 추가.
   - 자동 탐색 실패 시 사용자가 직접 IP를 입력하여 등록할 수 있는 수동 입력 옵션 통합.
2. **명시적 노드 등록 명령어 (`add-node`)**:
   - `vega add-node <IP/Host>` 명령어를 통해 새로운 노드를 즉시 검증하고 등록하는 기능 구현.
   - 등록 시 Connectivity 테스트 및 OS 감지를 자동으로 수행하여 장부에 기록.
3. **SSH Config Self-Healing (`sync-ssh`)**:
   - `vega sync-ssh`: 장부(KB)에 등록된 노드들을 바탕으로 `~/.ssh/config` 파일을 자동 생성 및 업데이트.
   - 시스템 통합을 통해 터미널 전역에서 베가 노드에 별칭으로 즉시 접근 가능하도록 연동.
4. **Real-time Health Monitoring (TCP Probe)**:
   - `vega status` 출력 시 22번(SSH) 포트 실시간 스캔을 통해 즉각적인 `ONLINE/OFFLINE` 판별 로직 추가.
   - `last_success` 기록에만 의존하지 않고, 현재 시점의 실시간 가용성을 보장.
4. **AI 의도 및 명령어 최적화**: 자연어 요청을 시스템 명령어로 매핑하는 추론 능력 고도화 및 SSH 연결 안정성 옵션(BatchMode) 강제 적용.
5. **고해상도 대시보드**: AI 별칭, 실시간 상태, 로드율, 태그를 포함한 통합 관제 화면 제공.
6. **SSH Connectivity Hardening (Exit Code 255 대응)**:
   - SSH 명령어 생성 시 `-o BatchMode=yes -o StrictHostKeyChecking=no` 옵션을 필수적으로 포함하도록 AI 지침 수정.
   - 사용자 개입이 불가능한 자동화 환경에서의 무한 대기 및 연결 실패(255) 문제를 원천 차단.
7. **Deep Scanning Status (실시간 심층 진단)**:
   - `vega status <target>` 명령어를 통해 타겟 노드의 OS 이름, 커널 버전, 디스크(/) 가용량을 실시간으로 스캔하여 보고하는 기능 탑재.
   - 단순 생존 확인을 넘어 실제 시스템 리소스 상태를 즉각 파악 가능.

## 완료된 세부 구현 사항
- **데이터 구조**: `src/knowledge.rs` 내 `tags`, `kernel`, `cpu_load` 필드 추가.
- **컨텍스트 엔진**: `src/context.rs` 내 KB 데이터를 AI 컨텍스트에 강제 주입하는 동기화 로직 구현.
- **실행 레이어**: `src/executor/status.rs` 내 실시간 TCP Health Probe 로직 탑재.

## 시니어의 한마디
"장부(KB)는 시스템의 지도요, 실시간 감시(Probe)는 시스템의 맥박이다. 이제 베가는 지도를 보며 맥박을 짚는 진짜 SRE 에이전트의 면모를 갖췄다."

# v0.0.11: 인터페이스에 로컬 LLM 추가 및 안정화

## 목표
사용자가 베가 설정 시 클라우드 LLM과 로컬 LLM을 더 직관적으로 선택할 수 있도록 인터페이스를 개선하고, 로컬 LLM(Ollama 등) 지원을 추가하며, 시스템 관리 도구로서의 신뢰성과 탐색 능력을 확보한다.

## 작업 내용
1. **`vega setup` 인터페이스 개편**:
   - 1) Cloud LLM (자동 선택): 환경 변수 및 파일 시스템에서 API 키를 자동 검색하여 설정.
   - 2) Cloud LLM (수동 선택): Gemini, ChatGPT, Claude 중 직접 선택.
   - 3) Local LLM: 로컬에서 실행 중인 LLM 엔드포인트 입력.
2. **로컬 LLM 프로바이더 구현**:
   - Ollama 호환 API 지원.
   - 엔드포인트 및 모델 설정 기능.
3. **자동 검색 로직 강화**:
   - 여러 개의 API 키 발견 시 리스트 형태로 출력 및 선택 기능 제공.

## 완료된 세부 구현 사항 (안정화)
1. **Ollama 연동 및 안정화**:
   - `OllamaProvider`에 `/api/tags` 엔드포인트를 연동하여 실행 중인 모델 목록을 자동으로 불러오고 선택할 수 있도록 구현.
   - Ollama API의 `"format": "json"` 모드를 활성화하여 로컬 모델의 답변 형식을 강제.
   - 텍스트 내 JSON 블록 추출 로직을 추가하여 모델의 사족(conversational filler) 문제 해결.
2. **원격지 식별 및 안전성 강화 (Deterministic Dispatcher)**:
   - `STORAGE:` (클라우드/rclone)와 `HOST:` (SSH) 접두사를 도입하여 리모트 객체의 타입을 명확히 구분.
   - **Safety Interceptor**: `ssh` 또는 `scp` 명령이 `STORAGE:` 리모트를 대상으로 할 경우 실행 전 즉시 차단하는 하드코딩 제약기 구현.
   - `RemoteMasker`를 고도화하여 식별자 매핑 시 타입 접두사를 포함하도록 수정.
3. **Identity Discovery (에이전트 자아 정체성)**:
   - `hostname -I` 및 `hostname` 명령을 통해 로컬 IP와 호스트명을 수집하는 로직 추가.
   - 시스템 프롬프트 최상단에 에이전트의 현재 위치(호스트명, IP)를 주입하여 모델의 상황 인지 능력 강화.
4. **SSH 탐색 강화**:
   - `~/.ssh/config` 뿐만 아니라 `~/.ssh/known_hosts`를 파싱하여 가용한 호스트 후보군을 대폭 확대.
   - 가용 호스트가 없을 경우 무의미한 명령 생성 대신 `needs_clarification`을 통한 사용자 피드백 유도.
5. **Fleet Maintenance (글로벌 메인터넌스)**:
   - `vega update --fleet`: 플릿 전체 노드를 순회하며 시스템 정보(커널, 로드 애버리지)를 갱신하고 상태를 점검하는 통합 명령어 구현.
   - `KnowledgeEntry` 확장: 원격지의 커널 버전 및 실시간 CPU 부하 정보를 저장하도록 데이터 구조 고도화.
   - **지능형 대시보드**: `vega status` 시각화를 개선하여 탐색된 노드와 등록된 노드를 명확히 구분하여 표시.

## 시니어의 한마디
"LLM의 환각은 프롬프트로 달래고, 시스템의 안전은 Rust 코드로 지킨다. 이제야 비로소 자율 운영 에이전트다운 뼈대가 갖춰졌군."
